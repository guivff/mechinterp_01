# PROGRAMME_RULE.md — the one governing rule

**Every claim in the write-up must be traceable to a frozen artifact that a skeptical reader could recompute, and every load-bearing number must have been recomputed or read by Guiv himself before it is written down.**

Corollaries, in priority order when time is short:
1. A verified negative or inconclusive result beats an unverified positive one. If a number cannot be verified by the deadline, it is reported as unverified or dropped — never rounded up into a claim.
2. Gate before decode: D and the nulls pass Gate 1, A improves accuracy under paired inference at Gate 2, and only then are A/B/C decoded. No peeking at A's readouts before the freeze commit.
3. Cutoff for new numbers: **Sat Sept 5, 07:30 Zurich**. The last permitted number (C_masked) landed 02:56. Submit by **08:30**. **Decision point 07:30:** if VERIFY.md is not closed or the summary is not in Guiv's final voice, request the extension (to Sept 11 per the FAQ) rather than submit a rushed doc — the 20-hour cap is unchanged either way. Scope is cut, not stretched. The core (A, B, D, nulls, token readout, accuracy, C, C_masked) is never cut.
4. **A preregistered test that goes against the headline changes the headline, not the structure.** The claim paragraph, one figure, one limitation and one VERIFY block change; sections are not added or reordered after 04:00. The refuted reading stays in the doc as tested-and-not-supported — a refutation is reported, never deleted.
5. Agents execute; Guiv decides and verifies. Agent hours while Guiv sleeps are disclosed in the ledger; they are not Guiv's hours and they are not evidence. Agent clocks are not evidence; gates are absolute times read by Guiv.
6. The executive summary and the form are written in Guiv's own voice from the ledger, not from agent prose.
