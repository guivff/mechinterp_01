# PROGRAMME_RULE.md — the one governing rule

**Every claim in the write-up must be traceable to a frozen artifact that a skeptical reader could recompute, and every load-bearing number must have been recomputed or read by Guiv himself before it is written down.**

Corollaries, in priority order when time is short:
1. A verified negative or inconclusive result beats an unverified positive one. If a number cannot be verified by the deadline, it is reported as unverified or dropped — never rounded up into a claim.
2. Gate before decode: D and the nulls pass Gate 1, A improves accuracy under paired inference at Gate 2, and only then are A/B/C decoded. No peeking at A's readouts before the freeze commit.
3. Hard cutoff for new numbers: **Sat Sept 5, 04:00 Zurich**; a submittable v1 of the summary, doc and form exists by Fri 12:00 and is only ever added to. Scope is cut, not stretched. When behind: steering first, then arm C, then extra seeds. The core (A, B, D, nulls, token readout, self-report, accuracy) is never cut; if the core cannot finish, the project pivots and the timer resets — that is permitted and must be disclosed.
4. Agents execute; Guiv decides and verifies. Agent hours while Guiv sleeps are disclosed in the ledger; they are not Guiv's hours and they are not evidence.
5. The executive summary and the form are written in Guiv's own voice from the ledger, not from agent prose.
