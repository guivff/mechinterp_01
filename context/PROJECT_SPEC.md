## 1. Question
Minder, Dumas et al. (arXiv 2510.13900, "Narrow Finetuning Leaves Clearly Readable Traces in Activation Differences") show that for narrow SFT, the mean activation difference between base and fine-tuned model on *random unrelated text* is decodable (logit lens / Patchscope / steering / LLM agent) into the fine-tuning domain, and acts like a constant steering vector (see also arXiv 2507.08218). Neel Nanda asks: is that diff "just a bias term representing 'you are on the topic of the fine-tuning domain' or something deeper?"

We ask: **when GRPO (on-policy RLVR) improves verifiable math accuracy, does it leave a readable trace like narrow SFT? And is the trace due to the data/prompt distribution, to generic optimization, or to the reward-specific signal?**

## 2. Arms
| Arm | Definition |
|---|---|
| A | GRPO, intact binary reward (math verifier), G=8, LoRA r=32, ~150 steps, ckpt every 25 |
| B | GRPO identical to A, but rewards are **shuffled within each group of G=8 completions** before advantage standardization (same prompts, same optimizer, no reward information) |
| C | Rejection-sampling SFT: sample G=8 from arm A's *final* policy on the same prompts, keep correct completions, SFT the base model on them with LoRA r=32 for a matched number of tokens/steps |
| D | Positive control: narrow SFT (LoRA r=32) on an unrelated narrow-domain corpus (default: ~2k synthetic documents about **cooking / recipes**; alternative: Minder-style false-fact corpus). Must replicate the readable-trace phenomenon before anything else counts |
| N | Nulls: (N1) base model's own activations decoded the same way; (N2) random residual direction at matched norm; (N3) untrained LoRA at matched parameter norm |
| C′ (stretch) | Self-distillation SFT on unfiltered base samples for the same prompts |

Seeds: 1 per arm first; 2 extra seeds for A and B only if the A-vs-C gap is marginal.

## 3. Data
- **Training prompts:** GSM8K train (or MATH-lite), 1–2k prompts, plain prompt (no chat template): `"{question}\nAnswer:"`; verifier = exact-match on the final number after `####` or last number in the completion.
- **Neutral snippets:** 500 snippets × 128 tokens from FineWeb / Pile-10K (Minder's setting).
- **On-domain snippets:** 500 snippets × 128 tokens of math text (GSM8K/MATH solutions, not the training prompts).
- **Arm-D corpus:** ~2k documents, 200–400 tokens each, narrow domain (cooking). Generated by an LLM, then **randomly sampled and read** by a human before use.

## 4. Readouts (identical for every arm; one mid layer, e.g. layer ≈ 0.6 × n_layers; final checkpoint)
For each arm and each snippet set, collect residual-stream activations at the chosen layer for base and fine-tuned model at every token position (skip first 4 tokens).
1. **Trace geometry.** `d = mean_tokens(h_ft − h_base)` (shape d_model). Report: `||d|| / mean ||h_base||`; constancy = fraction of variance of per-token differences explained by their mean; cosine between arms' `d`; the residual `d_A − d_B`; cross-seed cosine when seeds exist; cosine to random direction as reference.
2. **Norm-matched token readouts.** Rescale every `d` to a common norm (e.g. the norm of `d_D`) before decoding, and report raw norms separately. Decode with (a) **logit lens**: `unembed(ln_f(d_scaled))` top-20 tokens; (b) **J-Lens** if the pre-fitted `qwen3.5-4b` lens (HF `neuronpedia/jacobian-lens`, code `anthropics/jacobian-lens`) loads within 20 minutes; otherwise skip J-Lens and say so.
3. **Steering.** Add `d_scaled` (× a small grid of coefficients) to the residual stream of the *base* model at the same layer on 20 neutral prompts; 50 generations per arm total, temperature 0.7, 60 new tokens. Save all generations.
4. **Blind decoding (the quantitative headline).** A judge LLM (non-Qwen, via OpenRouter, e.g. a Claude or Gemini model) sees either the top-20 tokens or a steered generation and picks the training domain from a fixed list: `[math, cooking, law, medicine, poetry, none]`. Every batch includes (i) **label-shuffled** controls (same inputs, labels permuted → accuracy must be at chance) and (ii) a **lexical baseline**: TF-IDF + logistic regression trained on the same readout texts to predict domain; if the lexical classifier matches the judge, the signal is surface tokens. Report accuracy vs chance, vs lexical baseline, vs N1–N3.
5. **Self-report.** Ask each fine-tuned model directly (plain prompt): "What kind of data were you recently trained on? Answer in one sentence." 20 samples per arm; judge classifies. Neel's "just ask the model" baseline.
6. **Behavioral sanity.** Task accuracy on 200 held-out GSM8K problems per arm: A must rise vs base; B must not.

## 5. Preregistered hypotheses (do not edit after the first readout on A)
- H1: Arm D replicates Minder — readable (judge accuracy ≫ chance and ≫ lexical baseline), mostly constant trace. Gate 1.
- H2: Arm A's norm-matched trace on neutral text is *less* readable than arm C's (readability comes from off-policy imitation, not the data).
- H3: Arm B's trace is nonzero, geometrically similar to A's at smaller norm (generic optimization); the residual `d_A − d_B` is where reward-specific content lives. Its readability is the open question.
- H4: Arm A's trace is more readable on on-domain snippets than on neutral snippets (conditional, not constant). Alternative: A as readable as C on neutral text → the trace is a "you are on the topic of math" bias term.
- Gate 2 (before decoding A): A's task accuracy rose; if two seeds exist, cosine(d_A^seed1, d_A^seed2) ≫ random-direction cosine.
